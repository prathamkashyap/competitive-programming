# AGENTS.md

Instructions for AI coding agents and automated tooling working in this repository.

## Repository context

Competitive programming solutions and notes, primarily Codeforces, organized by
problem rating. Contains C++/Python/Java solutions, templates, documentation,
and tooling under `scripts/`.

CI runs `validate` (`.github/workflows/cpp-validation.yml`), which performs
syntax-only compilation across all C++ files. Keep it green.

## Commit messages

Use simple, imperative, developer-style messages. Describe what the change does,
in the imperative mood, as if instructing a colleague.

```
Add repository statistics
Improve profile retrieval
Verify external profile data
Update platform statistics
```

Match the existing history, which reads like:

```
Add Codeforces Solutions 1348B, 295A
Harden CI validation and external statistics
Improve browser rendering with better headers and context
```

Guidelines:

- Start with a capitalised verb: `Add`, `Fix`, `Update`, `Remove`, `Improve`, `Harden`.
- Keep the subject line under roughly 72 characters.
- Do not end the subject with a period.
- Use the present tense, imperative mood.
- Omit the subject's type prefixes entirely. Do **not** use Conventional Commits:
  no `feat:`, `fix:`, `refactor:`, `docs:`, `chore:`, `test:`, `ci:`, `perf:`,
  `style:`, `build:`, or `BREAKING CHANGE:` markers.
  A handful of older commits use these prefixes; they are historical, not a
  pattern to follow.
- Bullet lists in the body are acceptable when a change genuinely needs
  explanation. Omit them for routine solution additions.

## Authorship and attribution

These are hard requirements, not preferences.

- **Do not add `Co-Authored-By` trailers.** Not for a human, not for a bot, not
  for any tool. No exceptions.
- **Do not add AI or agent attribution** of any kind. Specifically excluded:
  `Generated with ...`, `Generated by ...`, agent names, bot logins, model
  names, or any `noreply` bot identity.
- Do not impersonate, merge, or substitute for a human author in metadata.
  Commit author and committer must remain the repository owner,
  Pratham Kashyap (`prathamkashyap`, GitHub id `77629675`).
- Do not set `Co-Authored-By` via `git commit --trailer`, `git config`, a
  `prepare-commit-msg` hook, or any other mechanism.

Automated agent contributions are an authoring-process matter for the human
owner. Attribution belongs to the repository owner, full stop.

## Scope and safety

- Do not force-push, rewrite published history, or delete branches without
  explicit written approval.
- Do not amend or rebase commits that are already pushed unless asked.
- Do not add generated artefacts, build output, or IDE state to the repository.
- Keep changes scoped to the request. Unrelated refactors make review harder and
  put CI at risk.

## Before committing

- Confirm the change is intentional and scoped.
- Run the local validation so CI stays green.
- Re-read your commit message against the policy above. If it carries a
  `Co-Authored-By` trailer, an agent credit, or a Conventional Commit prefix,
  it is not ready to commit.
